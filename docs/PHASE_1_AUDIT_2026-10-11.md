# مراجعة الحقيبة التأسيسية وقرار الجاهزية
تاريخ المراجعة: 11 أكتوبر 2026 (توقيت الرياض).
مصادر المراجعة: مجلد Drive الذي زوّد به صاحب المشروع، ومستودع Jassar1441/Wifqa.
لم تُعدّل ملفات الحقيبة الأصلية.

## ما وصل وما يغطيه
المجلد يحتوي 18 ملفًا: تسع وثائق تأسيس في docs، سجل المهام planning/المهام.csv، README وAGENTS و.gitignore، قالبي بلاغ داخل .github، وثلاث صفحات HTML للوحة التأسيس ومعايير البحث ونموذج بحث البطارية.
الوثائق تغطي الميثاق، النطاق، التصميم التقني، الجدول، الاختبارات، المخاطر والخصوصية، القرارات، تحقق السوق، ودفتر الأفكار.
وردت في قائمة المرفقات تسمية «download»، بينما الجرد المباشر للمجلد أظهر .gitignore في موضع الملف غير المفسر. يلزم مطابقة هذه النسخة محليًا إذا كان المقصود عنصرًا مستقلًا.

## خلاصة الحالة
الحقيبة موجودة، والمرحلة التأسيسية موثقة بدرجة جيدة. المستودع الخاص موجود الآن، ويمكن قراءة محتواه وكتابة فرع وطلب مراجعة عبر ربط GitHub الحالي. التطبيق لم يبدأ، ولا توجد اختبارات تشغيلية بعد.
تصف الحقيبة المنتج الأول بأنه وكيل تسوق للمنتجات المتخصصة؛ وتذكر أن أول حالة استخدام لبطارية درون معتمدة. لا تعتبر «وين أحصله» و«لفتة» منتجات معتمدة، فهي محفوظة للأفكار فقط.
تسجل docs/04 خطة 45 يومًا، وتضع اكتشاف السوق والتصميم بعد التأسيس. لم تُجرَ مقابلات السوق بحسب سجل المهام؛ وهذا عمل لاحق، ولا يلزم اختلاق نتائج لإغلاق العمل الوثائقي.

## المواصفات المعتمدة للتجربة
بناءً على توجيه صاحب المشروع باعتماد ما طُبّق في نموذج البطارية، يعتمد هذا العمل قيم الواجهة الموجودة مرجعًا لمعايير نموذج التجربة:
- بطارية LiPo قابلة للشحن، 11.1V.
- السعة من 1500 إلى 1800mAh شاملًا الطرفين.
- الأبعاد القصوى 71×33×23mm.
- XT60 يظهر كمعلومة في النموذج، لكنه ليس مرشحًا إلزاميًا؛ توافقه مع الجهاز غير مؤكد.

| الموضوع | النموذج المطبق | ما تسجله الحقيبة أو المقترحات السابقة | الإجراء |
|---|---|---|---|
| السعة والأبعاد | 1500–1800mAh؛ حد 71×33×23mm | docs/02 وdocs/05 تسجل 1800–2000mAh و71×32×22mm؛ وظهر سابقًا 1800mAh و80×37×27mm | اعتماد قيم النموذج لهذه التجربة، ومزامنة ملفات المصدر لتطابقها |
| الجهد والكيمياء | LiPo، 11.1V | متوافق مع الحقيبة | تثبيتهما في مجموعة المعايير |
| XT60 | معلومة مع إظهار أن التوافق غير مؤكد | ملف 05 لا يجعله مرشحًا | إبقاؤه خارج شروط القبول |
| التقنية | Next.js وTypeScript مقترح في docs/03 | React مع Vite مقترح في ورقة التجربة | يظل قرار المرحلة الثانية قبل إنشاء التطبيق |
| فئة التجربة | بطارية الدرون مثبتة في قرار D-007 | إكسسوارات الجوال ظهرت في ورقة التجربة | تبقى بطارية الدرون ضمن نطاق التجربة الأولى |
| حالة الجاهزية | GitHub خاص قائم وتم التحقق من القراءة والكتابة عبر فرع وPR | README وCSV يصفان حالة أقدم | مزامنة وصف الجاهزية في ملفات المصدر |

النموذج الذي فُحص واجهة HTML تجريبية؛ لا يدل على بحث حي أو تطبيق تشغيلي أو نتائج سوقية.

## قرار إغلاق المرحلة الأولى
**بوابة اعتماد مواصفات النموذج G0 مغلقة:** اعتمد صاحب المشروع القيم المطبقة في واجهة البطارية، وأُعدت عشرة أمثلة اختبار اصطناعية متوافقة معها. هذا يغلق قرار مواصفات التجربة ويسمح ببدء المرحلة الثانية.

تبقى مزامنة docs/02 وdocs/05 وdocs/07 وسجل المهام الأصلي في مجلد المصدر حتى تعكس القرار؛ لم تُعدّل ملفات Drive الأصلية ضمن هذه المراجعة. وتبقى مقابلات السوق واختبارات التطبيق ومصدر البيانات الحي أعمالًا منفصلة، ولا تُعد منجزة هنا.
## الخطوات التالية
1. بدء المرحلة الثانية بمزامنة وثائق المصدر مع معيار النموذج المعتمد وتحديث سجل القرار.
2. حسم التقنية قبل إنشاء التطبيق؛ المقترح العملي للتجربة الأولية هو React مع Vite، ويبقى اختيار Next.js/TypeScript واردًا إذا احتاج المنتج خادمًا منذ البداية.
3. فتح فرع عمل وتجهيز واجهة عربية RTL قابلة للتشغيل محليًا.
4. إضافة بيانات اختبار اصطناعية موسومة، وتنفيذ المسار الأولي دون متجر حي أو إنفاق أو نشر.
5. مطابقة الحالات العشرة الاصطناعية مع معايير القبول الاثني عشر وتشغيلها عند وجود التطبيق.
6. التحقق من الصلاحية والشروط والتكلفة قبل استخدام أي مصدر بيانات حقيقي.
7. بدء مقابلات السوق في مرحلة الاكتشاف، وتسجيل نتائجها منفصلة عن الاختبارات الاصطناعية.
8. مزامنة README وCSV مع وضع GitHub الفعلي ومراجعة بوابة الجاهزية.
