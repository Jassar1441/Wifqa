# وفقًا | معالجة مشكلة مصادر بيانات المنتجات — خطة تشغيل 13 أكتوبر 2026

**الحالة: بحث أولي موثّق من مصادر رسمية، بلا تكامل حي أو اتفاق شراكة أو موافقة قانونية حتى الآن.**
**هدف المنتج:** العثور على المنتج نفسه والموديل/النسخة الصحيحة، ثم مقارنة البائعين حسب السعر الإجمالي إلى السعودية، التوفر، الشحن والمدة. قرار الشراء عند العميل. لا نتائج مضللة.

## القرار الأول: الترخيص قبل كتابة الموصل
- يُمنع افتراض أن امتلاك API أو وجود سعر منشور يتيح إعادة نشر البيانات ضمن مقارنة أسعار تجارية.
- **أمازون السعودية:** اتفاقية الشركاء الحالية تنص على أن موقع الشريك لا يشمل أداة مقارنة أسعار إلا إذا وافقت أمازون؛ استخدام بيانات برنامج الشركاء خارج الغرض المرخص له له قيود. لا يبدأ تكامل المقارنة في WIFQA اعتمادًا على Creators API دون موافقة مناسبة للمقارنة عبر المتاجر (وتحقق من شروط العرض والتخزين والروابط والفترة الزمنية)، رغم أن Creators API يتيح بحث الكتالوج. مصدر رسمي: https://affiliate-program.amazon.sa/help/operating/policies و https://affiliate-program.amazon.com/creatorsapi/docs/en-us/introduction .
- **نون:** يوجد برنامج تسويق بالعمولة يعرض كتالوج منتجات: https://affiliates.noon.com/ar ، لكن API الموثّق https://noon-docs.noonpartners.dev/ يخدم البائعين والشركاء المُخوَّلين وبيانات عروضهم، وليس دليلًا على صلاحية شاملة للبحث في كل نون أو إعادة عرض البيانات التجارية. احصل على إثبات نطاق الاستعمال أولًا.
- **سلة (Salla):** الوثائق الرسمية: https://docs.salla.dev/products ، https://docs.salla.dev/doc-421118 . واجهة قراءة منتجات المتجر /products و/sku/{sku} بصلاحية products.read ونظام OAuth بموافقة التاجر. **صلاحية القراءة لا تعني تلقائيًا ترخيص إعادة العرض العام**؛ اتفق مع التاجر على نطاق النشر.
- **زد (Zid):** https://docs.zid.sa/start-here و https://docs.zid.sa/webhooks : Merchant API لمنتجات/مخزون/شحن المتاجر المصرح بها، وإشعارات تحديث المنتجات. يلزم تصريح التاجر واتفاق إعادة العرض، مع التحقق من حقوق حفظ النصوص والصور.
- **موازن:** https://muwazin.me/data/ يعرض API بيانات مقارنة البقالة السعودية؛ نطاقه محدود بالبقالة وتبقى شروط العقد والتكلفة والتغطية/الترخيص غير معتمدة لدينا. لا يحوّل نطاق «وفقًا» العام إلى بقالة فقط.

## أفضل مسار بداية (أولوية P0): متجران متعاونان على سلة/زد
1. إنشاء سجل مصادر مرشحة بدون اتصال أو تسجيل حسابات، مع تقييم قدرة مصدرين **متمايزين** على توفير نفس النسخة من منتج شائع.
2. الحصول على **إذن صريح من كل صاحب متجر** للقراءة والتخزين المؤقت وإعادة العرض في صفحة مقارنة الأسعار، والاحتفاظ بالإثبات وتاريخ ونطاق الترخيص. لا إرسال رسائل أو إنشاء حسابات أو منح صلاحيات باسم المالك إلا بعد موافقته.
3. يجهّز المبرمج **موصلًا محليًا mock/fixture** يقبل حقول منتجات Salla/Zid المعلنة من أمثلة الوثائق الرسمية، ولا يرسل طلبات حيّة أو يستخدم رموز دخول فعلية. يحول الحقول إلى compareExternal في مسودة PR1؛ يُسمّي البيانات synthetic بشكل واضح.
4. بعد الترخيص، استعمال صلاحيات القراءة الأدنى products.read مثلاً، بدون orders/customers/read_write، وحفظ رموز OAuth في مخزن أسرار خارج GitHub والكود.
5. جلب نموذج/sku/mpn/gtin والنسخة/السعة/الحجم والسعر والمخزون والرابط ومصدر كل حقل ووقت التحقق. لا تخلط اختلاف العبوة أو شرط اللون/السعة بالمطابق.
6. الشحن إلى أبها، الضريبة والرسوم ومدة التوصيل لا تستنتج من بيانات الكتالوج أو `in_stock`. تحقق عبر طريقة مصرح بها من متجر الوجهة/الشحن. إن غابت، تظهر **«غير مؤكدة»** ويُحجب إجمالي غير موثق عن تصنيف «الأرخص شامل الوصول».
7. تمكين تحديث على طلب البحث عند الترخيص وضمن الحدود، ثم إشعارات تحديث المنتج/المخزون حيث يتيح المصدر. `last_checked_at` لكل ادعاء لا لكل تشغيل فقط. عند انقطاع المصدر أو قدم الدليل، تنتقل النتيجة إلى «بحاجة للتحقق»، لا تؤخذ من الكاش باعتبارها متوفرة.
8. تأجيل أي تعميم واسع إلى ما بعد مراجعة الجودة وموافقة المالك.

## الخطة البديلة (P1) إذا لم نجد شريكًا خلال 5 أيام عمل
- لا تتوقف واجهة WIFQA: قدّم خدمة **مقارنة روابط يحددها المستخدم** لمنتجين/أكثر، مع قراءة مسموحة بحسب شروط المصدر، ومراجعة يدوية للمعلومة التي لا يمكن التحقق منها آليًا.
- لا تستخدم تقنية تتجاوز CAPTCHA أو قيود الدخول أو robots أو نسخ بيانات غير مرخّص؛ ولا تجعل المستخدم يعتمد على سعر أو توفر غير مثبت.
- تقدّم مقارنة جزئية واضحة وفصل للمجهول؛ **لا نعلن نجاح العثور على منتج متوفر قابل للشحن إذا لم يتأكد ذلك**.
- يمكن اختيار مزود بيانات مقارنات مرخّص كبديل إذا كانت شروطه وتسعيرته تسمح بخدمتنا دون اشتراك غير مرخص من المالك.

## مصفوفة الاختبار قبل قبول مصدر واحد
| فحص | شرط النجاح |
|---|---|
| الإذن/الحقوق | سجل نطاق القراءة وإعادة العرض/الصور/التخزين، وحدود النداءات والكلفة والمدة، مثبت وموافق عليه |
| المنتج نفسه | 10 حالات اختبار، **صفر تطابق كاذب** في الموديل والنسخة والحالة والكمية |
| المخزون | لا يُعرض غير المتوفر ضمن النتائج المؤكدة؛ unknown خارج ترتيب المتوفر |
| إجمالي السعر | السعر + الشحن + الضريبة غير المشمولة + الرسوم - خصم مثبت، أو «لا يمكن تحديد الإجمالي» |
| الوجهة | أبها مدعومة بدليل، وإلا تكتب «التوصيل إلى أبها غير مؤكد» |
| freshness | وقت المصدر لكل سعر ومخزون وشحن؛ التعامل مع انتهاء صلاحية الدليل وتعطل API |
| السلامة | لا رموز وصول في GitHub؛ سجل استجابة الشبكة لا يكشف مفاتيح أو بيانات مشترين |
| تجربة الجوال | RTL، رابط المتجر، بدائل منفصلة، لا زر شراء من «وفقًا» |
| فشل الخدمة | موصل غير متاح → نتيجة غير مؤكدة وليس تحويلها إلى مؤكد بالبيانات المؤقتة |

## برنامج 5 أيام عمل — قابل للتنفيذ دون إنفاق
- **اليوم 1:** توثيق الخيارات والشروط والمخاطر؛ تنفيذ نسخة mock لشكل استجابة متجر على الأقل. *حالة الآن: البحث الرسمي والقرار والخطة موثّقان، موصل mock لم ينفذ ضمن هذا الملف.*
- **اليوم 2:** خريطة الحقول من Salla/Zid إلى عقد WIFQA، وتصميم اختبارات تطابق وشحن/مخزون، مع QA.
- **اليوم 3:** تشغيل 10 حالات اصطناعية من مصدرين شبيهين بالمتاجر مع فشل متعمد وفصل النسخ.
- **اليوم 4:** تقرير قابلية شراكات فعلية، وما يحتاج موافقة المالك للتواصل أو إنشاء حساب أو صلاحية.
- **اليوم 5:** قرار **Go / No-go** لبدء مصدر حي واحد أو بدء المقارنة بروابط يعرضها العميل، من دون اختراع مصادر.
