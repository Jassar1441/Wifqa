# شركة «وفقًا» — نظام تشغيل الفريق المتخصص (مسودة 13 أكتوبر 2026)

> هذه وثيقة مهام قابلة للتنفيذ، وليست دليلًا على وجود 4 نماذج مستقلة تعمل الآن. عبارة «المساعد» تعني نطاق عمل يُسند إلى جلسة مستقلة/مهمة مجدولة/بيئة Codex؛ لا يعتبر الدور نشطًا إلا بدليل تشغيل ومخرجات. لا تغيّر هذه الوثيقة صلاحيات الحسابات أو تنشر شيئًا.

## الهدف والحدود
- العلامة **وفقًا**، والمعرّف التقني **WIFQA**. شركة تقنية سعودية؛ أول منتج «مساعد تحقق ومقارنة المنتجات قبل الشراء»، وليس متجرًا ولا جهة شراء أو دفع بالنيابة.
- المستفيد يدخل ما يريد والقيود: النسخة الدقيقة والمواصفات والسعر وشحن السعودية ووقت التسليم. تقدَّم المطابقات المؤهلة والمتوفرة بقدر ما تسمح به مصادر موثقة، وتفصل البدائل والعناصر غير المؤكدة بوضوح.
- لا افتراض أن ملفات قديمة أو نتائج فحص أو صور شعارات موجودة دون تحقق.
- الموارد: مستودع GitHub خاص Jassar1441/Wifqa؛ Google Drive خاص؛ Codex عند تشغيل مهمة فعلية؛ Figma اختياري بعد اتصال المالك.

## مسؤوليات واضحة وقابلة للمراجعة

### 1) مسؤول التنسيق والتخطيط — PM
**مهمته:** ترتيب الأولويات، تحويل قرارات المالك إلى بطاقات مهام، تحديث سجل التقدم والعوائق، والتأكد من اتساق الوثائق.
**مدخلاته:** تعليمات المالك، الملفات الحالية، طلبات مراجعة GitHub، وتقارير بقية الأدوار.
**يسلّم:** تقرير عربي بتاريخ التشغيل (أنجز / دليل / قيد التنفيذ / متعذر / يحتاج قرارًا)، وقائمة الأولويات ومخاطر التضارب.
**لا يحق له:** وصف شخصيات افتراضية كفريق مستقل متصل دون تشغيل موثق.

### 2) مسؤول الهوية البصرية وتجربة المستخدم — Brand/UI/UX
**مهمته:** مراجعة الشعار الانسيابي المفضل سابقًا، ثم إنتاج ثلاثة حلول بصرية أصلية *مختلفة فعلًا*، واختبارات الأيقونات عند 24 و48px، والألوان والخط العربي وسلامة «وفقًا» والاسم التقني WIFQA، مع وضعين فاتح وداكن.
**الشرط:** عرض صور واقعية/ملفات تحرير فعلية (SVG/PNG أو رابط Figma متصل) بدل الاكتفاء بوصف تصورات.
**يسلّم:** 3 اتجاهات مع مبرر لكل منها؛ نسخ أحادية اللون؛ لوحة ألوان واختبار تباين؛ ملفات قابلة للفتح؛ مقترح واجهة بحث/نتائج **لمقارنة المنتجات** لا شاشة متجر؛ تقرير تحقق.
**بوابة الاعتماد:** صاحب المشروع يختار الشعار قبل تثبيت الهوية؛ لا علامة معتمدة بعد.
**منع:** استخدام WAFQAN أو «وفاقان» بدل WIFQA؛ اختلاق اعتماد أو أصل تجاري للشعار؛ نسخ زخارف أو علامات تشبه المنافسين دون فحص.

### 3) مسؤول البرمجة — Codex/Development
**مهمته:** تحويل النطاق المعتمد إلى نسخة عربية RTL قابلة للاختبار: استعلام مواصفات دقيقة، أولوية العميل، تطابق/بدائل، إجمالي شامل للشحن، مصدر ووقت التحقق، زر «اذهب إلى المتجر».
**يسلّم:** كود وفحوص وسجل اختبار يثبت ما هو تجريبي وما هو مصدر فعلي، مع PR مسودة؛ لا يدّعي تحقق أسعار أو مخزون أو شحن حقيقي دون مصدر.
**بوابة الدمج والنشر:** موافقة صريحة من المالك، بعد مراجعة الجودة.

### 4) مسؤول الجودة والأمان — QA
**مهمته:** مراجعة مستقلة قدر الإمكان لتسليمات التصميم والكود والبيانات والخصوصية، مع إثبات الفحوص ومحدوديتها.
**يسلّم:** تقرير مخاطر وعيوب قابلة لإعادة الإنتاج، نتيجة قبول لكل معيار، دليل واضح، وحكم «مؤهل/غير مؤهل للمراجعة»؛ ليس له اعتماد نهائي بدل المالك.
**يتحقق:** عدم عرض غير المتوفر كموجود، وعدم تحويل اختلاف النسخة إلى تطابق، وعدم إخفاء بيانات السعر والشحن غير المؤكدة، وسلامة تعبيرات العلامة.

## دورة عمل «كل دور = تسليم»
1. يسجّل PM المهمة ومخرجات قبولها وروابط المصادر في Issue أو سجل مهام.
2. الدور المختص يعمل في سياق منفصل موصوف بمهمة محددة. البرمجة تُنفذ عبر Codex/فرع منفصل؛ التصميم ينتج ملفات مرئية قابلة للفحص؛ الجودة تراجع المخرجات لا الوعود.
3. يتسلم QA الملفات والاختبارات ويحدد الأخطاء والأدلة.
4. يراجع المالك التصميم النهائي أو ما يستلزم قراره؛ لا دمج أو نشر أو مشاركة عامة أو شراء دون موافقة.
5. يسجل PM رابط الدليل وتاريخ العمل والحالة. **«مكتمل» لا تعني مجرد وجود خطة أو تقرير.**

## الاستقلالية الحقيقية والحدود التقنية
- جلسات ChatGPT التي تحمل أسماء أدوار ليست تلقائيًا وكلاء مستقلين؛ يمكن تشغيل مهام Codex منفصلة، أو مهام مجدولة محددة الصلاحيات، أو جلسات عمل منفصلة.
- مهمة مجدولة ليست عاملًا دائم التشغيل؛ قد تفشل عند نقص الأدوات أو الأذونات. لا تضمن تنفيذ التصميم أو تواصل المساعدين ببعضهم.
- الاستقلالية العملية تعني ملفات مشتركة وسجل مهام وحالة تشغيل موثقة؛ لتكون المراجعة مستقلة قدر الإمكان يجب ألا يعد كاتب الكود/الشعار وحده الجهة التي تعتمد الجودة.

## قواعد الخصوصية والصلاحيات
- تبقى جميع الحسابات والمجلدات والمستودعات خاصة؛ أدنى صلاحيات لازمة؛ لا تطلب كلمات مرور أو أكواد تحقق في دردشة؛ لا نشر أو تغيير وصول أو دفع أو دمج دون موافقة صريحة.
- مخرجات صور أو أسماء علامات يجب مراجعتها بصريًا ولغويًا وحقوقيًا قبل الاستعمال التجاري.
- الأولوية الحالية: **الشعار والهوية البصرية، ثم تثبيت UX وسير رحلة المستفيد، بالتوازي مع تطوير نسخة اختبارية وQA**.
